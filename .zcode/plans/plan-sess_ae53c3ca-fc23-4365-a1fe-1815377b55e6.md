# Plan: Remediación Verify SDD-Phase-Agents (4 CRITICAL + WARNINGS + Superficie MCP)

## Contexto

El verify completo (#2416) sobre los 131 tasks / 14 suites marcó **status: blocked, NO ARCHIVABLE**. Hallazgos:
- **4 CRITICAL** (C-1 a C-4): falsos verdes por tests que no ejercitan lo que dicen.
- **Hallazgo estructural**: 131 tasks marcadas sobre una **librería que nadie llama** — no existe superficie MCP.
- **~15 WARNINGS** abiertos (SG-4/5, DL-5/6, init-round, worktree-fingerprint, CP-12/15, EF-6, PC-6, PE-16).

Decisión del usuario: **alcance total** (4 CRITICAL + todos los WARNINGS) + **construir la superficie MCP** + puente **SQLite directo (Opción B)** para el `McpToolClientPort`.

Las correcciones siguen el principio del brief: **los tests que son falsos verdes hay que BORRARLOS Y REESCRIBIRLOS, no extenderlos** — si el fix de apply solo agrega casos, el falso verde sobrevive.

## Fase 2 — Cambio de puertos (fundación para C-1 y C-2)

### F2.1 — `SddArtifactStorePort` con versionado (para C-1)
Archivo: `src/ports/sdd-artifact-store.port.ts`.
Cambio de firma (no es fix local, lo exige el diseño §9.12):
```ts
export interface CheckpointRecord { readonly content: unknown; readonly version: number; }

export interface SddArtifactStorePort {
  writeArtifact(key, content): Promise<void>;           // sin cambios
  readArtifact(key): Promise<string | null>;             // sin cambios
  readCheckpoint(key): Promise<CheckpointRecord | null>;  // era unknown|null
  writeCheckpoint(key, content, expectedVersion?: number): Promise<{ version: number }>;
}
```
`writeCheckpoint` con `expectedVersion` rechaza (throw) si la versión actual ≠ expectedVersion (concurrencia). Sin `expectedVersion` = write incondicional (para los casos que no compiten).

Toca: puerto + adaptador PMC + todos los call sites de `readCheckpoint`/`writeCheckpoint` (checkpoint.ts, project-record.ts no — ese usa writeArtifact).

### F2.2 — `SemanticGatewayHttpPort` con `AbortSignal` (para C-2 y SG-5)
Archivo: `src/ports/semantic-gateway-client.port.ts`.
```ts
export interface SemanticGatewayChatRequest {
  readonly endpoint, model, apiKey, prompt, maxTokens;
  readonly signal?: AbortSignal;   // NUEVO
}
export interface SemanticGatewayHttpPort {
  chatCompletion(request: SemanticGatewayChatRequest): Promise<SemanticGatewayChatResponse>;
}
```
Esto le da a `callSemanticGateway` un abort real (SG-5 hoy es Promise.race — el request queda abandonado, no abortado) y permite que `sddParseRequest` herede el timeout gratis vía un `AbortController`.

## Fase 5 — Puente McpToolClientPort (Opción B: SQLite directo)

### F5.1 — Adaptador SQLite
Archivo nuevo: `src/infrastructure/pmc/sqlite-mcp-tool-client.adapter.ts`.
Implementa `McpToolClientPort` contra `MEMORY_DB_PATH` (resuelto como en `.opencode/opencode.json` → `.planning/project-memory-context/memory-db.db`).
- Usa `node:sqlite` (`DatabaseSync`) — Node ≥22.5, el repo requiere ≥24. ✓
- `callTool("pmc-agent-memory_store", {key, content, kind})` → `INSERT OR REPLACE INTO memories (id, content, category, tags, created_at, updated_at, access_count, last_accessed_at, version, status, origin) VALUES (?, ?, 'other', '[]', ?, ?, 0, ?, <next-version>, 'active', 'sdd-plugin')`. Donde `id = key`, `content = content`. Retorna `{version: <new-version>}`.
- `callTool("pmc-agent-memory_recall", {key})` → `SELECT content, version FROM memories WHERE id = ?`. Retorna `{content: row?.content ?? null, version: row?.version ?? 0}`.
- Los triggers FTS (`memories_ai/_au`) se disparan solos en INSERT/REPLACE.
- `tags` siempre `'[]'` (JSON string, NOT NULL).
- WAL mode: acceso concurrente OK para reads; writes transaccionales cortos.
- Nota documentada: esto **acopla al esquema privado de agent-memory-mcp** (decisión del usuario, Opción B pragmática). Comentario en el archivo explicando el trade-off vs SS-8 literal.
